# 本地配网与凭据管理设计

更新时间：2026-09-24  
状态：设计已定稿第一版；运行时实现将分阶段、默认保持旧行为  
适用对象：ESP32-C6 网关；Zigbee 节点不需要 Wi‑Fi/MQTT 凭据

## 1. 为什么需要产品化配网

当前网关固件在编译时通过本地头文件提供：

- Wi‑Fi SSID/密码；
- MQTT Broker 地址；
- MQTT 用户名/密码。

这适合实验开发，但不适合产品化：

1. 换家庭 Wi‑Fi 必须重新编译/烧录；
2. 每个客户环境不同，不能为每台设备单独编译；
3. 凭据容易进入构建日志、备份或截图；
4. 后续支持 TLS、证书轮换、设备搬迁时流程不顺；
5. 工厂生产和用户自用应使用同一套可重复流程。

目标：**凭据优先保存在设备本地 NVS，编译时凭据只作为实验室回退；生产固件可关闭编译时回退。**

## 2. 设备分类

### 网关

需要：

- Wi‑Fi SSID/密码；
- MQTT URI；
- MQTT 用户名/密码；
- MQTT Client ID；
- 后续 TLS CA 证书或证书配置；
- 设备恢复出厂设置方式。

### Zigbee 节点

通常不需要用户输入凭据：

- Zigbee network key 由 Zigbee 栈/NVRAM 管理；
- 节点通过 secure join/rejoin 接入协调器；
- 电池节点只需要保存低功耗策略、上报周期和本地校准值。

## 3. 配网方式比较

| 方式 | 优点 | 风险/缺点 | 当前建议 |
|---|---|---|---|
| SoftAP + 本地网页 | 不依赖手机厂商，电脑/手机都能连，流程可控 | 需要 HTTP server/captive portal 和状态机 | **第一推荐** |
| BLE Provisioning | 手机体验较好，设备不需要切 AP | 需要 BLE 共存、App/小程序或通用 GATT 工具 | 后续版本 |
| SmartConfig | 手机操作简单 | 兼容性/安全性和广播抓包问题较多 | 不优先 |
| WPS | 流程短 | 路由器支持减少，安全性一般 | 不推荐 |
| 串口配置 | 实现简单 | 普通用户不会用，日志可能误触复位 | 保留给工厂/调试 |

## 4. 推荐状态机

```text
启动
  ↓
读取 NVS 配置
  ├─ 配置有效：进入正常 Wi‑Fi STA / MQTT
  └─ 配置缺失/损坏：进入配网 AP
                ↓
        用户连接设备热点
                ↓
        打开本地配置网页
                ↓
        提交 Wi‑Fi/MQTT 参数
                ↓
        输入校验并写入 NVS
                ↓
        切换到 STA 模式测试
          ├─ 成功：进入正常运行
          └─ 失败：保留旧配置，回到配网 AP 显示错误
```

已配置设备遇到路由器暂时不可用时，不应立即删除凭据；超过启动宽限后可进入“配网/修复 AP”，但必须保留原配置，方便用户返回原网络。

## 5. SoftAP 与本地网页建议

### 5.1 AP 命名

建议使用设备短标识，例如：

```text
IoT-Home-XXXX
```

其中 `XXXX` 由网关 MAC 后两字节或短 ID 生成，不泄露完整 MAC 也便于区分多台设备。

### 5.2 AP 安全性

短期原型可使用开放热点，但必须满足：

- 仅在配网模式启动；
- 有超时限制；
- 只能访问本地配置服务；
- 不转发网络；
- 用户在设备旁边短时间操作。

产品化建议使用设备标签上的一次性配对码作为 AP 密码，或进入网页后要求输入设备本地 PIN。当前没有标签和屏幕，暂不强行启用。

### 5.3 网页字段

第一版字段：

- Wi‑Fi SSID（可手输，后续可提供扫描列表）；
- Wi‑Fi 密码；
- MQTT broker 主机/IP；
- MQTT 端口；
- 是否使用 TLS；
- MQTT 用户名；
- MQTT 密码；
- 网关 ID（高级字段，默认自动生成）。

网页提交必须限制长度，避免超长字段导致栈缓冲问题。密码输入框不得在页面回显明文，不通过日志打印。

## 6. NVS 数据布局

建议 namespace：

```text
iotcfg
```

建议键：

| 键 | 类型 | 含义 |
|---|---|---|
| `version` | u8/u16 | 配置结构版本 |
| `wifi_ssid` | str | Wi‑Fi SSID |
| `wifi_pass` | str | Wi‑Fi 密码 |
| `mqtt_uri` | str | 完整 MQTT URI 或由 host/port/tls 生成 |
| `mqtt_user` | str | MQTT 用户名 |
| `mqtt_pass` | str | MQTT 密码 |
| `mqtt_cid` | str | MQTT Client ID |
| `flags` | u32 | TLS、自动重连、是否已完成首次配网等 |

默认最大长度：

- SSID：32 字节 + 结尾；
- Wi‑Fi 密码：64 字节 + 结尾；
- MQTT 用户名/密码：64 字节 + 结尾；
- MQTT URI：160 字节 + 结尾；
- Client ID：64 字节 + 结尾。

写入原则：

- 只在用户提交配置或恢复出厂时写入；
- 保存成功后再切换网络；
- 不因每次联网成功而写 NVS；
- 不在日志输出任何值；
- 配置版本不匹配时忽略并要求重新配网。

## 7. 与现有固件的兼容方式

第一阶段只增加“读取 NVS 配置”的基础组件：

1. NVS 有有效配置：优先使用 NVS；
2. NVS 没有配置：继续使用现有本地编译配置；
3. NVS 配置不完整：忽略该项并回退；
4. 默认不启用 SoftAP，避免影响已验证网关；
5. 后续有硬件时再接入配网页面和恢复按钮。

这样当前实验室流程不会被立即改变，也不会因为无法配网导致设备不可用。

## 8. 恢复出厂 / 重新配网

当前网关没有确认过专用按键，不能随便把某个引脚定义成清除按钮。建议后续硬件增加一个按键，或使用 OLED 菜单。

可选触发方式：

- 长按专用配置按钮 5–8 秒；
- 网关已联网时，在本地网页/API 中确认清除；
- 连续上电失败达到规则后进入修复 AP，但不自动清除凭据；
- 串口工厂命令，仅限调试版本。

清除内容：

- Wi‑Fi/MQTT 配置；
- 用户写入的 TLS 配置；
- 用户自定义网关 ID。

不得默认清除：

- Zigbee NVRAM；
- Zigbee 网络密钥；
- RF policy；
- 本地校准数据，除非用户明确选择恢复全部出厂设置。

## 9. 安全演进

### 当前原型

- NVS 中保存明文凭据；
- 不打开匿名 MQTT；
- 配网 AP 限制在本地短时操作。

### 产品阶段

建议结合硬件能力评估：

- NVS encryption；
- Secure Boot / Flash encryption；
- TLS CA 证书安全存储；
- 设备唯一证书或每设备 MQTT 凭据；
- 设备标签一次性配对码。

这些涉及 eFuse，一旦配置可能不可逆，必须留给用户确认，不能在夜间自动执行。

## 10. 分阶段实施计划

1. **阶段 1（低风险）**：NVS 配置存取组件；
2. **阶段 2（低风险）**：网关启动时优先读取 NVS，缺失则回退编译时配置；
3. **阶段 3（需硬件）**：SoftAP/HTTP 页面，不改变正常运行路径；
4. **阶段 4（需硬件）**：网络扫描、连接测试、失败提示；
5. **阶段 5（产品化）**：NVS encryption、设备证书、恢复按钮/OLED 菜单；
6. **阶段 6（生产）**：关闭编译时凭据回退。

## 11. 不做事项

- 不在夜间启用 NVS encryption、Secure Boot 或 Flash encryption；
- 不自动清除现有配置；
- 不打印 Wi‑Fi/MQTT 凭据；
- 不将任何真实密码写入文档或示例；
- 不把 SoftAP 配网直接接入尚未硬件验证的网关主流程。
