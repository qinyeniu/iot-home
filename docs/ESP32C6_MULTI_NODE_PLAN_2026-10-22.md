# ESP32-C6 多功能终端节点扩展计划（2026-10-22）

## 0. 目标
用现有的一颗 **ESP32-C6 SuperMini** 构建一个**多功能环境+姿态监测终端节点**，通过 Zigbee 接入现有网关（MQTT/FastAPI 链路），
既包含常规实验箱元素（OLED、按键、LED、蜂鸣器），又引入创新点（6 轴姿态、本地 OLED 菜单、低功耗电池供电），
并尽量复用已有硬件（AHT20、BH1750、IP5310/TP4056/MT3608、KY-040 旋钮方案）。

## 1. 现有资源盘点（避免重复）
| 已有节点 | 功能 |
|---------|------|
| node_zigbee | AHT20 温湿度 + BH1750 光照（Zigbee ED 上报） |
| node_battery_sensor | SED 低功耗版（AHT20+BH1750，light sleep） |
| node_switch / node_switch_zigbee | 开关节点 |
| node_combined | 综合节点 |

**避免重复**：不再做纯温湿度/光照/开关节点。

**已有硬件**：
- ESP32-C6 SuperMini ×1（新，本计划使用）
- AHT20 模块、BH1750 模块（可复用）
- IP5310 ×2 + TP4056 电池盒 ×2 + 18650 ×2（供电）
- MT3608 常开升压模块 ×2（待购，供电）
- KY-040 旋钮模块（网关已用，本节点可选用小型按键）

## 2. 节点定位：多功能环境 + 姿态监测节点（"Q 节点"）
灵感来源：**xyzroe/Q_sensor**（GitHub 开源，ESP32-C6 Zigbee 多传感器空气质量传感器）。

### 2.1 传感器选型（常规 + 创新）
| 类别 | 传感器 | 说明 | 参考价 |
|------|--------|------|--------|
| 温湿度（已有） | AHT20 | 复用现有模块 | 已有 |
| 光照（已有） | BH1750 | 复用现有模块 | 已有 |
| 气压（新增） | BMP280 | 气压/高度，常规实验箱 | ~3 元 |
| 6 轴姿态（创新） | MPU6050 / QMI8658C | 加速度+陀螺仪，可做跌倒检测/倾斜报警 | ~5 元 |
| 人体存在（创新） | 5.8G 雷达模块（HLK-LD2410 等） | 存在感应，接 GPIO 中断 | ~15 元 |
| 本地显示 | 0.96" OLED（已有网关同款） | 本地显示传感器值 + 菜单 | ~8 元 |
| 执行反馈 | 有源蜂鸣器 + RGB LED | 报警/状态指示 | ~3 元 |
| 交互 | 1-2 个按键 | 本地切换显示/触发报警 | ~1 元 |

### 2.2 创新功能
1. **本地 OLED 菜单**：旋转/按键切换显示（温湿度、光照、气压、姿态角、人体存在）。
2. **跌倒/倾斜检测**：MPU6050 加速度突变检测，触发蜂鸣器 + Zigbee 报警上报。
3. **人体存在感应**：5.8G 雷达，有人/无人状态上报，可联动开关节点。
4. **电池电压监测**：利用 ESP32-C6 ADC 采样电池电压，随 Zigbee 上报。
5. **低功耗模式**：默认睡眠（参考 node_battery_sensor 的 SED light sleep），事件/周期唤醒。

### 2.3 复用已有硬件
- **AHT20 + BH1750**：直接复用现有模块。
- **MT3608 升压模块**：18650 → TP4056 电池盒 → MT3608 → 5V 给节点供电（常开不休眠）。
- **IP5310**：作为备用/移动电源方案（需手动按键开机）。

## 3. 系统架构
```
[ESP32-C6 SuperMini 节点]
   ├─ AHT20 (I2C) ─ 温湿度
   ├─ BH1750 (I2C) ─ 光照
   ├─ BMP280 (I2C) ─ 气压
   ├─ MPU6050 (I2C) ─ 6轴姿态
   ├─ 5.8G 雷达 (GPIO) ─ 人体存在
   ├─ OLED (I2C) ─ 本地显示
   ├─ 蜂鸣器 + RGB LED (GPIO)
   ├─ 按键 (GPIO)
   └─ 电池电压 (ADC)
        │
        ▼ Zigbee (channel 26, ED/SED)
[网关 ESP32-C6]
   ├─ RF 功率控制、本地 OLED 菜单
   └─ MQTT → FastAPI → MySQL
```

## 4. 固件实现步骤
1. **新建工程** `node_multisensor`（或扩展 node_battery_sensor）。
2. **驱动层**：移植/编写 BMP280、MPU6050、雷达、OLED、蜂鸣器驱动。
3. **Zigbee 层**：复用现有 ZCL 上报框架（参考 node_zigbee / Q_sensor）。
4. **本地 UI**：小 OLED 菜单（可参考网关 local_control 简化版）。
5. **低功耗**：复用 node_battery_sensor 的 light sleep 框架。
6. **上报**：温湿度/光照/气压/姿态/人体存在/电池电压，标准 ZCL cluster 或自定义 cluster。

## 7. 里程碑
- **M1**：采购模块到货，搭建面包板（传感器全部 I2C，接线简单）。
- **M2**：移植驱动，I2C 扫描确认所有传感器地址。
- **M3**：Zigbee 入网 + 基础上报（温湿度/光照/气压）。
- **M4**：加入姿态/雷达/电池电压上报。
- **M5**：本地 OLED 菜单 + 蜂鸣器/RGB 反馈。
- **M6**：低功耗模式（SED light sleep）+ 电池供电实测。
- **M7**：文档 + 提交。

## 8. 与现有项目的兼容性
- Zigbee 信道 26、PANID 复用现有网关网络。
- 上报格式与现有 node_zigbee 保持一致（JSON telemetry → MQTT）。
- 网关本地控制菜单（Node Control）可显示该节点地址，实现远程/本地控制。

## 9. 风险与对策
| 风险 | 对策 |
|------|------|
| MPU6050 需要 5V 供电（模块常带稳压） | 确认模块是否 3.3V 兼容，必要时单独供电 |
| 雷达模块功耗较高 | 仅在需要时启用，或用 GPIO 控制供电 |
| I2C 多个设备地址冲突 | 每个传感器地址不同（AHT20=0x38, BH1750=0x23, BMP280=0x77, MPU6050=0x68），用 I2C 扫描确认 |
| 低功耗与雷达/OLED 冲突 | 默认睡眠，事件唤醒；OLED 仅在本地交互时点亮 |
