## 4. 数据模型

`iot_zb_node_t` 保存：

- 短地址和 IEEE 地址；
- active 状态和最后存活时间；
- 温度 `int16_t` 原始值，0.01°C；
- 湿度 `uint16_t` 原始值，0.01%；
- 照度 `uint16_t`，编码为 `10000 * log10(lux + 1)`；
- valid/dirty 位；
- On/Off valid/value；
- first_dirty_ms。

`iot_zb_node_store_t` 只描述调用方提供的数组和容量，组件本身不动态分配内存。`addr == 0` 是空槽；节点离开后保留最后节点状态，只把 active 置为 false 并清空 dirty。

- `iot_zb_node_find()`；

- `iot_zb_node_apply_onoff()`；
- `iot_zb_node_take_due()`；
- `iot_zb_node_build_telemetry()`。

遥测选择保持旧逻辑：

1. 温度、湿度、照度 dirty 全部到达时立即取出；
2. 部分样本等待 30000ms；
3. 取出后复制节点、清空 dirty，但保留 valid；
4. On/Off 进入 JSON，但不参与三要素完整性。

时间差使用 `uint32_t` 减法。JSON 构造使用 `snprintf` 并检查截断。

## 12. P0-2：RF-quiet Zigbee rejoin 第一阶段：PASS

### 改动内容

1. 删除旧的全局 `ZB_JOIN_BEFORE_WIFI` 开关；
2. 若 NVS `gwzb/child=1`，网关启动后先不启动 Wi-Fi/MQTT，由 Zigbee coordinator 先完成节点 rejoin；
3. 节点通过报告变为 active，且温/湿/光完整样本就绪后，才启动 Wi-Fi/MQTT；
4. 若 120 秒内未看到 active 节点，或看到节点后额外 30 秒仍无完整样本，则按超时路径启动 Wi-Fi/MQTT；
5. 没有历史子节点的网关保持原有行为，Wi-Fi 立即启动，不延迟云端上线；
6. `zb_persist_child_seen()` 已检查 NVS open/set/commit，失败时输出警告。

## 13. P1-4 Wi‑Fi 恢复策略组件化复审：APPROVE

复审范围：`firmware/common/iot_wifi_recovery_policy/` 新组件、网关根/`main` 的 CMake 接入、`main.c` 接入以及组件 README/主机测试。

结论：未发现阻塞问题，判定 **APPROVE**。主机测试执行通过：`100% tests passed out of 1`。

语义核对：

- retry 扫描时机保持为 2、3、4，以及 retry >= 8 后每 4 次；
- OK 清空空扫描计数并置 `environment_alive=true`；EMPTY 置 false 后递增；扫描硬件失败维持原证据；
- 空扫描达到 3 次才触发 deep sleep，quiesce destructive tail 预请求与实际计数阈值一致；
- boot watchdog 保持 grace 边界为严格大于 25000ms；`ever_connected`、grace、environment alive、reboot budget 的优先级与旧逻辑一致；
- 新组件无 ESP-IDF/FreeRTOS/Wi‑Fi 调用，纯函数边界清晰。

非阻塞项：

1. `iot_wifi_recovery_empty_scan_will_reach_limit()` 在 `empty_scans == INT_MAX` 时执行 `empty_scans + 1`，存在理论有符号整数溢出 UB；当前网关固定 3 次且第 3 次进入 deep sleep，实际不可达。建议改为 overflow-safe 比较（如已保证 limit > 0 时比较 `empty_scans >= empty_limit - 1`）。
2. 主机测试可补充 NULL/负计数、`SCAN_FAILED` 从 false 状态保持不变、INT_MAX 饱和与预测、非法枚举无副作用，以及负 `max_reboots` 拒绝路径。

## 14. P1-4 Wi‑Fi 恢复策略组件拆分：PASS

### 改动内容

1. 新增无硬件依赖组件 `firmware/common/iot_wifi_recovery_policy/`；
2. 将 retry 2/3/4 与 retry >= 8 后每 4 次扫描的判断抽为纯函数；
3. 将扫描成功、扫描失败、连续空扫描、deep sleep 阈值判断抽为纯逻辑；
4. 将 cold-boot watchdog 的宽限期、周边 RF 证据、warm reboot 预算判断抽为纯逻辑；
5. 实际扫描、断连、持久化、deep sleep、warm reboot 仍由 `main.c` 执行；
6. `uptime_ms` / `grace_ms` 使用 `uint64_t`，避免 32 位毫秒计数约 49.7 天回绕。
