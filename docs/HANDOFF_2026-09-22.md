## 2. 当前硬件与链路

| 角色 | 端口 | BASE MAC | 当前角色 | 备注 |
|---|---:|---|---|---|
| 网关 | COM6 | 98:88:E0:70:90:DC | Zigbee coordinator + Wi‑Fi/MQTT bridge | OLED 已拔，不影响链路 |
| 二合一节点 | COM5 | 98:88:E0:71:1B:A0 | AHT20/BH1750 传感器 + On/Off 继电器 | 短地址 0x82cb，rx-on-when-idle |

链路：

```text
REST API -> MySQL commands -> MQTT cmd topic
  -> 网关解析短地址与 command
  -> Zigbee ZCL On/Off cluster (0x0006) 单播
  -> 节点 EP10 On/Off server
  -> GPIO4 控制继电器

节点 OnOff state -> 原始 ZCL Report Attributes
  -> 网关缓存/转换 -> MQTT telemetry
  -> 后端 metrics 表（metric = on_off）
```

本次重启后网关日志显示当前 PANID 为 `0xd989`（channel 26）。节点仍以 `0x82cb` 正常加入，不影响云端设备 ID。后续不要因为 PANID 与早期实验室 PAN `0x2b9e` 不同而主动改网；只有重新 clean formation 时才使用代码里保留的固定 PAN 逻辑。

## 3. 代码改动

### 节点：`firmware/node_zigbee/main/main.c`

- 启动时配置 GPIO4 为输出并默认拉高；继电器模块为 3.3V **低电平触发**：LOW=吸合，HIGH=释放。
- 在原 EP10 的手工簇列表中继续加入三个测量 server cluster，并新增 On/Off server cluster（`ESP_ZB_ZCL_CLUSTER_ID_ON_OFF`，0x0006）。
- 注册/复用 `esp_zb_core_action_handler_register(zb_action_handler)`：
  - HA 库把标准 On/Off 命令转成 `ESP_ZB_CORE_SET_ATTR_VALUE_CB_ID`；
  - 校验 cluster=0x0006、attribute=0、size=1；
  - 调用 `relay_set()` 改变 GPIO4；
  - 100 ms 后发送一次 OnOff 状态 report。
- OnOff report 没有使用高层 `esp_zb_zcl_report_attr_cmd_req()`，而是沿用本工程传感器已验证的 raw APSDE-DATA 路径，构造 Boolean 类型（0x10）的 Report Attributes 帧。
- 代码审查后又增加可靠性处理：
  - 用独立的 relay report pending state 记录在途帧 sequence/attempts；
  - APS confirm 严格按 ASDU 长度与 Boolean 类型区分传感器帧（8 字节）和继电器帧（7 字节）；
  - 链路探测窗口占用 sequence 时，500 ms 后重排状态上报；本地提交失败或 APS 失败时最多尝试 3 次；
  - GPIO4 在 `app_main` 最开始配置并保持高电平，同时启用内部上拉；实际高安全负载仍建议加外部上拉。

### 网关：`firmware/gateway/main/main.c`

- 订阅 `iot-home/+/nodes/+/cmd`。
- `gateway_handle_node_cmd()` 从 topic 提取 `zb-XXXX`，解析 payload 中的 `command`：
  - `on` -> `ESP_ZB_ZCL_CMD_ON_OFF_ON_ID`（0x01）
  - `off` -> `ESP_ZB_ZCL_CMD_ON_OFF_OFF_ID`（0x00）
  - `toggle` -> `ESP_ZB_ZCL_CMD_ON_OFF_TOGGLE_ID`（0x02）
- 使用 `esp_zb_zcl_on_off_cmd_req()` 单播到节点，短地址/endpoint 均匹配。
- 网关 EP10 添加 On/Off client cluster。
- ZCL report callback 增加 cluster 0x0006：读取 1 字节 Boolean 值并转成 telemetry：
  - 立即发布 `{"data":{"on_off":0|1}}`
  - 后续完整传感器包发布 `{"data":{"temperature":...,"humidity":...,"lux":...,"on_off":0|1}}`
- main 组件已链接 cJSON（前序提交已完成）。

## 6. 踩坑：高层 OnOff report 断言

最初节点在 `relay_state_report_timer_cb()` 中使用：

```text
esp_zb_zcl_report_attr_cmd_req()
```

节点已经打印 `RELAY ON`，随后 ZBOSS 断言：

```text
Assertion failed .../zcl/zcl_general_commands.c:612
abort() was called
```

因此停止使用该高层 helper，改为 raw APSDE-DATA 自己构造 ZCL Report Attributes：

- frame control：server-to-client report，0x18
- command：Report Attributes，0x0a
- cluster：0x0006
- attribute：0x0000
- data type：Boolean，0x10
- value：1 字节，0 或 1

改用 raw report 后，on/off/toggle 均不再触发断言，传感器每 10 秒上报继续正常。
