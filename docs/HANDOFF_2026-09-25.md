## 3. 电池传感器阶段 2：采集与标准 ZCL 上报

### 3.1 修改范围

- `firmware/node_battery_sensor/README.md`

未修改现网 `firmware/node_zigbee`、网关固件、后端、前端或云服务器配置。

### 3.2 本阶段功能

- 每 60 秒读取 AHT20 温湿度；
- BH1750 使用 one-shot high-resolution 命令 `0x20`；
- 使用与现网节点一致的 raw APSDE-DATA 路径构造标准 ZCL Report Attributes；
- 温度为 `int16`，单位 0.01 °C；
- 湿度为 `uint16`，单位 0.01 %；
- 光照为 `uint16`，按 Zigbee 对数照度编码：`10000 × log10(lux + 1)`，并限制在 `0xFFFD`；
- 本地提交被拒绝时最多重试 3 次；
- 帧已经发出但 APS 未确认时，本阶段不做无线补报，等待下一个采样周期，以减少电量消耗；
- AHT20/BH1750 任一读取失败时，本地 ZCL MeasuredValue 会恢复为 invalid，并清除缓存样本对应 valid flag，避免网关主动 Read 读到陈旧值。

- COM5：现网节点；
- COM6：现网网关。

### 7.2 公网后端状态

先尝试公网后端：

```text
GET http://8.163.110.27:8000/api/devices/gw-001-zb-82cb/rf-policy?fresh=true
=> 404 Not Found
```

这说明公网后端仍未部署本地已完成的 RF policy API，与交接记录一致。本轮没有部署或重启远端服务。

随后使用 `tools/rf_power_config.py` 直连公网 MQTT。当前终端没有 MQTT 用户名/密码环境变量，因此走的是仍待关闭的匿名 MQTT 入口；未读取、打印或记录任何密码文件。

### 7.3 事务序列

| 顺序 | 操作 | 客户端结果 |
|---:|---|---|
| 1 | QUERY | `auto / -10 dBm` |
| 2 | SET 0 | `manual / 0 dBm` |
| 3 | SET -10 | `manual / -10 dBm` |
| 4 | AUTO | 40 秒内未收到匹配确认，超时退出 |
| 5 | 恢复后 fresh QUERY | `auto / -10 dBm` |

结论：AUTO 命令的确认帧遇到一次超时，但稍后 fresh QUERY 已确认节点真实状态为 `auto / -10 dBm`。处理过程中没有重复下发 AUTO，避免了“节点已执行但云端重复命令”的干扰。
