# OLED 显示屏技术文档

**更新时间**: 2026-09-09

## 屏幕规格

| 项目 | 值 |
|------|-----|
| 型号 | SSD1306 0.96" I2C |
| 分辨率 | 128 x 64 像素 |
| I2C 地址 | 0x3C |
| 颜色 | **黄蓝双色** |

## 黄蓝双色布局

```
行 0-15  (页 0-1):  黄色区域
行 16-63 (页 2-7):  蓝色区域
```

**示意图：**
```
┌─────────────────────────────┐
│      黄色 (0-15px)          │  ← 标题区
│      "IoT-Home GW"          │
├─────────────────────────────┤  ← 分界线 (16px)
│      蓝色 (16-63px)         │  ← 内容区
│  IP: 192.168.137.226        │
│  WiFi:OK  MQTT:OK           │
│  Up: 00:05:30               │
│  ZB NODES:0                 │
└─────────────────────────────┘
```

## UI 设计规范

### 布局原则

1. **黄色区域（标题区）**
   - 只放标题文字
   - 居中显示
   - y 坐标：4（上下留 4px 边距）

2. **蓝色区域（内容区）**
   - 放详细信息
   - 左对齐
   - 从 y=20 开始，每行间隔 12px

### 字体规格

| 项目 | 值 |
|------|-----|
| 字体大小 | 5x7 像素 |
| 字符宽度 | 6px（含 1px 间距）|
| 行高建议 | 12px |

### 居中计算公式

```
文字宽度 = 字符数 × 6
x 坐标 = (128 - 文字宽度) / 2
```

**示例：**
- "IoT-Home GW" = 11 字符 × 6 = 66px
- x = (128 - 66) / 2 = 31

### 推荐布局模板

```c
// 黄色区域：标题（居中）
oled_text(31, 4, "IoT-Home GW");

// 蓝色区域：详细信息（左对齐）
oled_text(0, 20, "IP:192.168.1.100");
oled_text(0, 32, "WiFi:OK  MQTT:OK");
oled_text(0, 44, "Up: 00:05:30");
oled_text(0, 56, "ZB NODES:0");
```

## 接线方式

| OLED 引脚 | ESP32-C6 引脚 |
|-----------|---------------|
| VCC | 3.3V |
| GND | GND |
| SDA | GPIO2 |
| SCL | GPIO3 |

**⚠️ 重要：SDA 和 SCL 不能接反！**

## 显示驱动方案：直接用乐鑫官方组件（2026-09-09 最终定稿）

**结论：不要自己手写 GDDRAM 分页刷屏，统一用官方组件
`espressif/ssd1306`（组件库版本 1.0.5，IDF >= 4.0 均可）。**

### 依赖（main/idf_component.yml）

```yaml
dependencies:
  espressif/ssd1306: "1.0.5"
```

### 用法（网关固件已采用，见 firmware/gateway/main/main.c）

```c
#include "ssd1306.h"
// I2C 必须先初始化为主机；速率用 100 kHz（杜邦线/飞线下最稳）
s_oled = ssd1306_create(I2C_NUM_0, 0x3C);   // 参数是 7 位地址
ssd1306_draw_string(s_oled, x, y, (const uint8_t *)"TEXT", 12, 1); // 6x12 字体
ssd1306_refresh_gram(s_oled);               // 一次整屏提交
```

### 为什么官方写法不闪（关键原理）

官方驱动初始化时把屏幕设为 **垂直寻址模式（命令 0x20,0x01）**，
并用 0x21/0x22 把列窗口设为 0-127、页窗口设为 0-7；
`ssd1306_refresh_gram()` 把 1024 字节帧缓冲放在**一次连续的 I2C 事务**里写出，
GDDRAM 地址按列严格自动递增。官方测试用例甚至 **100ms 刷一整屏（10Hz）都不闪**。

我们手写时犯过的错误（都不要再犯）：

| 错误做法 | 后果 |
|----------|------|
| 水平寻址(0x20,0x00)，每页单独发"页地址命令+128字节"，共 8 次事务 | 命令打断数据流，整屏出现**从上往下撕裂** |
| 只刷"变化的整页/脏矩形"且不重设地址 | **整行闪烁**，内部列指针错位时**花屏/错乱** |
| I2C 用 400 kHz | 杜邦线下偶发传输错误，表现为显示错乱 |

正确参数：**100 kHz I2C + 垂直寻址 + 单次连续事务 + 官方组件**，
需要降带宽就降低刷新率（网关用 500ms），不要自己做局部刷写。

### 本屏（双色模块）的方向修正

官方 `ssd1306_init()` 默认 SEG/COM 映射为 **A1 + C0**。
本机这块屏需要 **A1 + C8** 画面才正向，因此 `ssd1306_create()` 之后
要补发一条 0xC8 命令（组件没暴露发命令接口，直接用 I2C 发 0x00,0xC8）：

```c
static void oled_cmd_raw(uint8_t cmd_byte) {
    uint8_t buf[2] = {0x00, cmd_byte};   // 0x00=命令流
    i2c_cmd_handle_t h = i2c_cmd_link_create();
    i2c_master_start(h);
    i2c_master_write_byte(h, (0x3C << 1) | I2C_MASTER_WRITE, true);
    i2c_master_write(h, buf, 2, true);
    i2c_master_stop(h);
    i2c_master_cmd_begin(I2C_NUM_0, h, pdMS_TO_TICKS(100));
    i2c_cmd_link_delete(h);
}
// create 之后：oled_cmd_raw(0xC8);
```

若将来换屏发现画面上下颠倒 → 去掉 0xC8（用官方默认 C0）；
左右镜像 → 把 A1 改成 A0。

### 字体与黄蓝分区布局

- 官方字体：6x12（`c_chFont1206`，draw_string 传 chSize=12）、8x16（chSize=16），
  覆盖完整 ASCII 95 字符，行高按 12px 排。
- 双色屏物理分区（颜色由行决定，软件不能选色）：
  - 行 0-15（页 0-1）**黄色**：只放标题，6x12 字体放 y=2
  - 行 16-63（页 2-7）**蓝色**：内容行 y=16/28/40/52
  - 文字不能跨越 16px 分界线


## 2026-09-10 实机复测：官方组件方案作废，改用本地文本驱动（已目视通过）

**最新结论：** 本机使用 `espressif/ssd1306` 1.0.5 的 `ssd1306_draw_string(..., 12, 1)`
会出现用户描述的“完全错乱的诡异字”。源码复核发现两个问题：

1. 组件初始化中发送了 `0xDA`，但漏发 128x64 必需的参数 `0x12`，后续 `0xDB` 会被屏幕当作 `0xDA` 参数；
2. 组件 `c_chFont1206[95][12]` 被绘制函数按 12 列、每列 8 行输出，并非本文原先假设的普通 6x12 文本字库。

已在网关 `main.c` 内改为本地文本驱动，并经 COM6 实机目视确认正常：

- 标准 128x64 初始化，明确发送 `0xDA 0x12`，方向 `A1 + C8`；
- 5x7 ASCII 字库，字符步距 6px；
- 软件帧缓冲使用常规 page-major：`s_fb[page * 128 + x]`；
- 刷屏前转换为 vertical addressing 所需的列优先 1024 字节；
- 每帧一次 I2C 数据事务，I2C 100kHz；
- 黄色标题行 y=4，蓝色内容行 y=18/30/42/54，刷新周期 500ms。

本节实机验证通过；下方“直接用乐鑫官方组件”章节仅保留为踩坑记录，不再作为实现依据。

- 2026-09-10 深夜：`espressif/ssd1306` 1.0.5 依赖已从网关工程移除，本地驱动不依赖外部显示组件。
