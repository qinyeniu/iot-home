## 3. 本次节点固件改动

```text
C:/Users/HJB/Documents/iot-home/firmware/node_zigbee/main/main.c
```

新增能力：

1. 每个 ZCL 属性发送函数现在检查返回值。
2. 如果协议栈暂时拒绝 APSDE 发送请求，每项最多立即重试 3 次，每次间隔 200 ms。
3. 缓存最近一次有效且已完成 ZCL 缩放的值：
   - 温度：signed 16-bit，0.01 °C；
   - 湿度：unsigned 16-bit，0.01 %；
   - 光照：unsigned 16-bit，Zigbee log scale，`10000 * log10(lux + 1)`。
4. I2C 读取失败只计数和告警，不会把旧读数伪装成一次新的采样；但 APS 发送失败补传时可使用最近一次有效缓存。
5. 注册 APSDE-DATA confirm 回调。回调只做轻量计数并通过 FreeRTOS task notification 唤醒传感器任务，不在 Zigbee 栈回调中直接发包。
6. APS 确认失败后，传感器任务按 1 秒、2 秒退避，最多把最近一组完整缓存补传 2 次。
7. 每 60 秒输出一次 `REPORT_STATS`，包含 I2C 失败、发送尝试、入队失败、APS 成功/失败和自愈次数。

### 3.1 晚间续：AHT20/BH1750 读取加固

后续提交 `aae7f6c fix(node): validate sensor measurements` 又补齐了异常采样拦截：

1. AHT20 启动时只初始化一次，后续不再每轮重复发送初始化命令；如果启动初始化失败，之后会尝试恢复。
2. AHT20 读取状态字：
   - busy bit (`0x80`) 置位时拒绝本轮温湿度；
   - calibrated bit (`0x08`) 未置位时尝试重新初始化并拒绝本轮温湿度；
   - 温度限制在 `-40 ~ 85 °C`，湿度限制在 `0 ~ 100 %`。
3. BH1750 增加光照上限检查（`60000 lux`），异常值不缓存、不上报。
4. 读取结果区分为：
   - `i2c_th_fail` / `i2c_lux_fail`：I2C 总线或传输失败；
   - `th_invalid` / `lux_invalid`：芯片忙、未校准或数据越界。
5. 只有通过校验的数值才会更新 `s_last_sample` 和 ZCL 属性，避免坏数据进入云端，也避免坏数据污染 APS 失败后的补传缓存。
6. 文件头中信道注释已从错误的 25 更正为实际使用的 26。

常见串口日志：

DATA: {...,"th_ok":true,"lux_ok":true}

REPORT_STATS: rounds=... attempts=... queued=... aps_ok=... aps_fail=...

## 4. 为什么改为原始 APSDE-DATA 上报

最初保留 `esp_zb_zcl_report_attr_cmd_req()` 并注册 `esp_zb_aps_data_confirm_handler_register()` 时，节点和云端都正常，但统计持续为：

```text
aps_ok=0, aps_fail=0
```

对 ESP Zigbee 1.6.0 库头文件和预编译库符号确认后发现，该 confirm handler 是“带用户数据的 APS 帧”的发送结果回调；高层 ZCL helper 不经过这个用户 payload 回调路径。

因此最终做法是：

- 继续调用 `esp_zb_zcl_set_attribute_val()` 更新本地 ZCL 属性；
- 手工构造标准 ZCL Report Attributes 帧；
- 通过 `esp_zb_aps_data_request()` 发送到 coordinator 的 EP10；
- 设置 `ESP_ZB_APSDE_TX_OPT_SECURITY_ENABLED | ESP_ZB_APSDE_TX_OPT_ACK_TX`；
- 使用 APS confirm 作为自愈触发。

云端已经能正常解析这些标准 ZCL report，说明网关侧无需改动。

## 6. 下次建议

1. 如要验收失败自愈，可在节点刚发出一轮数据时短暂给网关断电 3-5 秒，再恢复，观察：
   - `REPORT_APS ... aps_fail` 增加；
   - 出现 `REPORT_SEND: reason=aps-repair`；
   - `repairs` 增加；
   - 网关恢复后云端继续收到数据。
2. 如果失败自愈造成过于频繁的补传，再调整 `REPORT_APS_REPAIRS` 或退避时间。
3. 后续低功耗阶段再把当前 RX-on-when-idle 稳定模式切回 sleepy/轮询，并重新评估父节点缓存和 APS 重试时间。
4. MQTT 认证迁移仍是独立任务，不要和节点上报自愈混在同一次部署/烧录窗口。
5. 后续如继续加固传感器链路，可优先考虑迁移到新版 `driver/i2c_master.h`，并评估 AHT20 CRC 校验；当前已先通过状态位和物理范围拦截坏采样。
6. 如果监视器无法用 `Ctrl+]` 正常退出，只能按完整命令行匹配并结束明确包含 `COM5` 的 `idf.py monitor` / `esp_idf_monitor` 进程树；结束前必须确认不是 COM6。
