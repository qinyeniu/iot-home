### 3.2 本阶段功能

- 每 60 秒读取 AHT20 温湿度；
- BH1750 使用 one-shot high-resolution 命令 `0x20`；
- 使用与现网节点一致的 raw APSDE-DATA 路径构造标准 ZCL Report Attributes；
- 温度为 `int16`，单位 0.01 °C；
- 湿度为 `uint16`，单位 0.01 %；
- 光照为 `uint16`，按 Zigbee 对数照度编码：`10000 × log10(lux + 1)`，并限制在 `0xFFFD`；
- 本地提交被拒绝时最多重试 3 次；
- 帧已经发出但 APS 未确认时，本阶段不做无线补报，等待下一个采样周期，以减少电量消耗；
- AHT20/BH1750 任一读取失败时，本地 ZCL MeasuredValue 会恢复为 invalid，并清除缓存样本对应 valid flag，避免网关主动 Read 读到陈旧值。

## 4. 硬件测试边界

1. 不切换网卡、不开关热点；
2. 不修改阿里云安全组、DNS、证书、MQTT Broker 或 VPN；
3. 不部署远程服务器；
4. 不整片擦 Flash、不擦 Zigbee NVRAM、不刷 bootloader/分区表；
5. 不把电池实验固件直接烧入现网 COM5 组合节点，除非用户明确知道该操作会替换现有继电器节点功能；
6. 打开 COM5/COM6 串口可能触发热复位，开始采集前需明确告知用户。

## 5. 硬件在线时建议顺序

1. 在用户确认允许串口复位后，分别采集 COM5/COM6 日志；
2. 先确认节点 secure rejoin、短地址、父链路和网关 MQTT 状态；
3. 跑短序列 QUERY → SET 0 → SET -10 → AUTO；
4. 如果时间允许，再启动 4–8 小时长稳定性复测；
5. 长测期间不改网络、不部署服务器；
6. 结束后分析日志并更新交接。
