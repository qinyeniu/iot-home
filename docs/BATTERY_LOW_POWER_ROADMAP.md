# 电池节点低功耗改造路线

更新时间：2026-09-25  
状态：路线已定稿；唤醒调度策略阶段 1 已离线实现并通过主机测试；未烧录、未接入现网  
适用工程：`firmware/node_battery_sensor`（独立电池传感器实验工程）

## 1. 结论先行

电池节点低功耗不能只靠 `esp_deep_sleep_start()`。需要同时验证：

1. Zigbee Sleepy End Device 的父节点缓存和 poll/keep-alive 间隔；
2. 芯片 light sleep、ZBOSS sleep、外设和传感器供电；
3. 唤醒、采样、发送、poll、重入睡眠的完整电流；
4. 命令延迟是否可接受；
5. 电池的脉冲放电能力和自放电。

当前推荐顺序：

```text
电流基线实测
  → 对齐 sample/poll 周期
  → 关闭/门控传感器与上拉
  → 继续优化 ZBOSS light sleep
  → 单独验证 deep sleep + rejoin
  → 事件唤醒和低电量策略
```

在实测证明收益前，不把现网节点改成睡眠节点，不把电池实验固件烧入 COM5 组合节点。

## 2. 当前固件真实状态

`firmware/node_battery_sensor` 当前已经具备：

- Zigbee Sleepy End Device（SED）；
- 关闭 idle RX；
- 启用 ZBOSS sleep 和 FreeRTOS tickless/light sleep；
- 默认 keep-alive/poll：60 秒；
- 默认采样和 ZCL 上报：60 秒；
- AHT20/BH1750 使用按需 I2C；
- BH1750 使用 one-shot，采样后自动断电；
- 未入网时不初始化 I2C；
- 本地 APS 请求被拒绝才有限重试；帧已发出但未确认则等下个周期；
- 不做 Flash 断网缓存。

这代表当前是 **ZBOSS 保持运行的 light sleep 路线**，不是断电式 deep sleep。RAM 和协议栈状态仍保留，优点是风险较低；缺点是理论睡眠电流可能高于完全 deep sleep。

## 3. 必须先做的硬件电流基线

至少记录以下状态的电流和持续时间：

| 状态 | 需要确认 |
|---|---|
| 空闲睡眠 | ZBOSS 是否真的进入 sleep，平均电流是多少 |
| poll | 唤醒、poll、收到父节点缓存/空结果、回睡耗时 |
| 采样 | I2C、AHT20、BH1750 的耗电和耗时 |
| ZCL report | 三条 ZCL report 的发送峰值和 APS confirm |
| poll+sample 合并 | 先 poll 再采样上报，是否减少一个睡眠周期 |
| 断网 | coordinator 不可用时的退避电流，不允许紧射频扫描 |

同时区分可能的漏电来源：

- USB 转串口芯片；
- LDO/稳压芯片静态电流；
- LED；
- AHT20/BH1750 供电；
- I2C 上拉；
- 上拉/分压电阻；
- Flash、I2C、IEEE 802.15.4 外设是否按预期下电。

“释放 I2C 控制器”不等于传感器断电。若传感器 VCC 仍连接主电源，仍可能消耗静态电流。

## 4. 采样和 poll 对齐策略

### 4.1 命令延迟边界

SED 的下行命令通常由父节点缓存，等设备 poll 时取回。因此：

- poll 间隔 60 秒：命令最坏延迟约 60 秒；
- poll 间隔 300 秒：命令最坏延迟约 5 分钟；
- poll 间隔 900 秒：命令最坏延迟约 15 分钟。

电池传感器可以接受这种延迟；电池继电器/安全类设备不应采用这种长间隔。

### 4.2 推荐实验配置

| 阶段 | 采样/上报 | poll/keep-alive | 目的 |
|---|---:|---:|---|
| 基线 | 60 秒 | 60 秒 | 验证功能和单次能耗 |
| 电池测试 1 | 300 秒 | 300 秒 | 验证父节点长缓存和平均电流 |
| 电池测试 2 | 900 秒 | 300 秒 | 平衡命令延迟与上报频率 |
| 深度睡眠实验 | 900/1800 秒 | 启动后 rejoin | 单独评估 deep sleep 成本 |

300 秒以上的 keep-alive 是否被当前 coordinator/父节点长期接受，必须实测；不能仅靠子节点配置推断。

### 4.3 合并唤醒

采样周期与 poll 同时到期时，建议顺序：

```text
唤醒
  → poll 取回缓存命令
  → 处理必要的本地配置
  → 读取传感器
  → 发送 ZCL report
  → 回睡
```

已新增的主机策略模块会把这种情况标记为 `POLL_THEN_SAMPLE`。

## 5. 唤醒调度策略模块

新增纯 C 模块：

```text
firmware/common/iot_battery_schedule/include/iot_battery_schedule.h
firmware/common/iot_battery_schedule/iot_battery_schedule.c
firmware/common/iot_battery_schedule/tests/test_iot_battery_schedule.c
```

该模块只计算下一次动作，不执行 I/O：

- `COMMISSION`：未入网时按退避时间继续入网；
- `POLL`：到达父节点轮询时间；
- `SAMPLE`：到达采样/上报时间；
- `POLL_THEN_SAMPLE`：两者同时到期；
- `LOCAL_EVENT`：按键/门窗等本地事件唤醒。

所有时间必须来自同一个单调 uptime 毫秒时钟，不能使用 NTP/墙钟时间；时间戳按 32 位毫秒计数自然回绕。poll/sample 间隔和 commission 的有效未来范围限定在 `1..INT32_MAX` 毫秒，错过或已经过去的 commission deadline 立即执行，避免无符号差值回绕成数十天。

未入网时即使有本地事件，也仍先返回 `COMMISSION`，本地事件由接入层锁存；已入网时 `LOCAL_EVENT` 立即返回，但它只表示先处理/去抖本地事件，不自动授权网络发送，`poll_due/sample_due` 会继续保留以便合并唤醒。

普通和 `-DNDEBUG` 主机测试均通过，覆盖过期 deadline、tick 原点跨越、未入网本地事件，以及本地事件分别与 poll/sample/两者到期同时发生。

接入前还需要：

1. 在电池工程中注册该公共组件；
2. 将 ZBOSS scheduler alarm 或 RTC 定时器与策略输出绑定；
3. 确认动作失败后的重排规则；
4. 硬件上验证实际唤醒和回睡。

## 6. 外设和电源门控

后续硬件应优先考虑：

- 用负载开关控制 AHT20/BH1750 的 VCC；
- 选择静态电流极低的负载开关；
- I2C 上拉只在传感器供电时接入，或使用带上拉控制的方案；
- 未使用 GPIO 设置为明确的输入/禁用状态，避免浮空；
- 关闭不必要 LED；
- 串口日志只在调试版本保留，量产版本降低日志级别。

若继续使用开发板，USB-UART 和 LDO 的静态电流可能让深度睡眠收益不明显。最终应以 PCB 设计验证。

## 7. Deep Sleep 的边界

### 7.1 为什么不直接默认启用

深度睡眠会停止 CPU 和大部分 RAM 内容保持。Zigbee 协议栈 RAM 状态不会像 light sleep 那样继续运行。唤醒后通常需要：

1. 重新初始化协议栈；
2. 从 NVRAM 恢复网络状态；
3. 执行 secure rejoin；
4. 等待父节点/TC 接受；
5. 再发送数据。

因此 deep sleep 的省电收益必须扣除重新入网的时间、峰值电流和失败重试成本。

### 7.2 Deep Sleep 实验验收

只有在 light sleep 电流仍无法满足目标时才进入该阶段：

- RTC 定时唤醒；
- 固定采样间隔，例如 900/1800 秒；
- 记录 rejoin 耗时和成功率；
- 验证 coordinator 不产生过期子设备缓存；
- 验证 rejoin 失败时低频退避，不持续扫网；
- 强制断电后仍能恢复；
- 不擦 Zigbee NVRAM，不改变网络密钥。

## 8. 事件唤醒

后续可增加：

- 本地按键；
- 门窗磁开关；
- PIR 等外部中断。

事件唤醒后应：

1. 去抖并确认状态；
2. 快速 poll；
3. 发送状态变化；
4. 回睡。

状态变化类事件不能等下一个长采样周期；但环境温湿度可以周期上报。

## 9. 电池选择

| 类型 | 优点 | 风险 |
|---|---|---|
| 2×AA/AAA | 容量高、脉冲能力通常较好 | 自放电和体积 |
| 18650/小型锂电 | 容量大、可充电 | 需要充电保护和电压转换 |
| CR2032 | 体积小 | Zigbee 发送峰值可能导致电压跌落 |
| Li-SOCl2 | 自放电低 | 脉冲能力和电容配置需专门设计 |

理论续航必须使用实际平均电流计算，并扣除电池自放电。纽扣电池尤其要验证 Zigbee 发射瞬间电压是否跌落导致复位。

## 10. 低电量策略

建议后续通过 ADC 或芯片电压估算电池状态，并设置：

- 正常模式；
- 低电量警告；
- 低电量时延长采样/poll 间隔；
- 保留一次关键状态上报；
- 避免在低电量下反复 rejoin 耗尽电池。

电池电压属于状态数据，不属于密钥；上报时可以包含电压和低电量标志。

## 11. 与服务器/前后端的边界

当前路线默认：

- 不改变前端页面；
- 不改变后端 API；
- 不改变 MQTT topic；
- 不启用 Flash 缓存；
- 网关继续按现有方式转发 ZCL report。

若后续支持远程修改采样间隔、poll 间隔或 OTA，必须单独设计：

- 参数范围和默认值；
- 命令确认与超时；
- 非法参数拒绝；
- 网关和后端展示；
- 设备断连时的命令状态。

这些属于接口/语义变化，必须写入设计文档并取得复审，不能和低功耗底层改造混做。

## 12. 验收目标

实际目标以电流测量为准，建议初始验收：

1. 入网后空闲无紧射频循环；
2. 60 秒 sample/poll 功能完整；
3. 300 秒长间隔下父节点不删除子节点；
4. 正常运行无 panic/reboot；
5. 传感器失败不导致频繁写 Flash；
6. 明确 sleep、poll、sample、report 的平均和峰值电流；
7. 根据实测建立续航模型，而不是先承诺固定续航月数。

## 13. 明确不做

- 不把电池固件烧入现网 COM5 组合节点；
- 不修改网关/前后端 API；
- 不自动启用 TLS/WSS/VPN；
- 不新增高频 NVS 写入；
- 不擦 Zigbee NVRAM；
- 不在没有电流实测时宣称 deep sleep 一定更省。
