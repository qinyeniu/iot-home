## 1. 当前服务与风险边界

当前系统涉及：

- Mosquitto MQTT：原生 MQTT/WebSocket；
- FastAPI 后端；
- MySQL；
- Grafana；
- ESP32-C6 网关通过公网 MQTT 接入。

已完成但尚未部署的准备：

- 后端/网关 MQTT 账号分离；
- 按网关 ID 限制 ACL；
- 关闭匿名访问；
- 保留旧共享账号短期迁移；
- 后端配置优先读取独立后端账号。

主要风险：

1. MQTT 若允许匿名，公网任何人都可能尝试发布命令；
2. 明文 MQTT 缺少传输层加密；
3. 安全组端口暴露过宽；
4. Grafana/API 也需要确认访问边界；
5. 服务器资源有限，证书续期、VPN、日志增长都要预留资源。

## 2. 执行前检查清单

建议维护开始前先记录：

1. 阿里云 ECS 规格：CPU、内存、系统盘剩余空间；
2. Docker 容器状态、重启次数和资源占用；
3. Mosquitto、FastAPI、MySQL、Grafana 当前日志时间范围；
4. 网关当前在线状态和最近遥测时间；
5. 当前安全组入方向规则；
6. 是否已有域名、域名是否备案、DNS 解析是否可控；
7. 是否有服务器快照或至少配置文件备份。

建议保留资源红线：

- CPU 常规负载尽量低于 60%；
- 内存至少保留 20% 空闲；
- 系统盘至少保留 25% 或 3–5 GB 空闲；
- MySQL、Grafana、Mosquitto 日志必须轮转；
- 不同时运行备份、镜像构建、证书申请、容器重启等高负载任务。

## 2.1 资源预算建议（小规格 ECS 初始值）

> 以下是后续维护窗口的建议初始值，不是今晚自动执行。用户的 ECS 约 1.6GB 内存，必须给宿主、Docker daemon、SSH/阿里云助手、突发备份保留余量。

建议先通过 `docker stats --no-stream`、`free -m`、`df -h` 观察 1–2 天，再分批加入限制；不要一次调整全部服务。

| 容器 | 建议内存上限 | 建议 CPU 上限 | 说明 |
|---|---:|---:|---|
| `iot-mysql` | `320M` | `0.35` | 旧 160M 曾有 OOM 线索；若仍 OOM，优先优化连接数/保留期，不盲目取消限制 |
| `iot-backend` | `160M` | `0.20` | 当前 compose 已有近似上限，可继续观察 |
| `iot-grafana` | `160M` | `0.20` | 看板加载/插件初始化会短时升高；先观察，再决定是否调整 |
| `iot-mosquitto` | `48M` | `0.10` | MQTT 很轻，但公网连接风暴时需限制 |

目标是常规运行时：

- 系统总内存使用低于 80%，至少保留 250–350MB 可回收/空闲内存；
- CPU 5 分钟负载低于约 60%；
- 系统盘使用低于 80% 告警、85% 必须处理、90% 停止新的高风险操作；
- Docker 相关日志、镜像和卷不能无限增长。

### 2.1.1 容器日志轮转

建议后续在每个 compose 服务中加入等价配置，或配置 Docker daemon 默认日志轮转：

```yaml
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"
```

按四个服务计算，普通容器 stdout 日志理论上限约 120MB。实际日志过多时应降低日志级别，而不是把 `max-file` 调得很大。

### 2.1.2 数据保留和磁盘清理

- MySQL 遥测数据建议先采用 30–90 天在线保留，超期数据以后再做归档；
- 删除历史数据必须小批量、分页执行，避免一次大事务锁表或产生大量 binlog；
- 不配置自动 `docker system prune -a`，避免误删仍需使用的镜像或卷；
- 清理前先执行只读检查：`docker system df`、`docker images`、`docker volume ls`；
- 备份和证书申请不要与容器重建、镜像拉取同时进行。

### 2.1.3 轻量告警（后续选择一种）

二选一即可，避免重复监控：

1. 使用阿里云云监控的基础 CPU、内存、磁盘告警；
2. 使用一个轻量脚本每天检查一次磁盘/内存/容器状态，只在异常时通知。

不建议在小规格 ECS 上再堆叠一套重型 Prometheus/Grafana remote-write/Loki；当前服务器 Grafana 主要面向业务看板，资源监控应尽量轻量。

## 3. 阶段 A：账号与 ACL（先于 TLS）

目标：先解决匿名和越权发布，不改变传输地址和端口。

详细可执行命令、验收和回退步骤见 `docs/ALIYUN_MQTT_ACL_DEPLOYMENT_RUNBOOK.md`。
推荐顺序：

1. 备份 Mosquitto、Docker Compose 和后端环境配置；
2. 检查已有账号，不盲目重复创建；
3. 部署密码文件和 ACL；
4. 迁移阶段短期保留旧共享账号；
5. 网关仍使用自己的账号；
6. 后端使用后端独立账号；
7. 验证通过后再移除旧账号。

ACL 原则：

- 后端可以订阅/处理所有网关的 telemetry/status/rf_policy；
- 网关账号只能访问自己的 `iot-home/{gateway_id}/...`；
- 网关只能发布自己的上行主题，订阅自己的命令主题；
- 任意账号不得跨网关发布命令；
- 不允许匿名。

验收项：

- 匿名连接被拒绝；
- 网关可以正常上线；
- 后端可以正常入库；
- 网关账号不能访问其他网关主题；
- API/Grafana 仍可查询；
- 容器日志没有持续认证失败。

回退：

- 恢复旧 Mosquitto 配置；
- 短期重新启用迁移用旧账号；
- **不通过打开匿名回退**。

## 4. 阶段 B：TLS / WSS

TLS 需要先确定访问方式。

### 4.1 有域名（推荐）

建议准备一个域名，例如专门用于 MQTT 的子域名，并确认 DNS 指向阿里云 ECS。

优点：

- 证书容易自动续期；
- ESP32-C6 可以使用 CA 根证书校验；
- 浏览器 WebSocket 使用 WSS 更顺。

建议端口：

- `8883`：MQTT over TLS；
- `9003` 或另行约定：MQTT over WebSocket Secure；
- `80/443`：证书申请或反向代理使用，按实际方案开放。

### 4.2 无域名 / 自签证书

不推荐作为第一选择。

问题：

- 设备端必须写入并信任特定 CA；
- 证书轮换复杂；
- 浏览器和设备调试体验较差；
- 容易因为 CN/SAN、时间错误导致连接失败。

如果暂时没有域名，优先考虑 VPN/内网方案，而不是直接暴露自签 TLS。

### 4.3 证书与续期注意事项

需要规划：

- 证书存储位置和权限；
- 证书到期前提醒；
- Mosquitto 重载配置而不是粗暴重启；
- 证书更新后设备信任的 CA 是否变化；
- 自动续期任务的 CPU/磁盘占用。

ESP32-C6 端建议只内置 CA 根证书，不内置服务器私钥。证书更新时只要仍由同一 CA 签发，设备无需重新烧录。

## 5. 阶段 C：VPN / 内网访问

可选目标：公网不再直接暴露 MQTT/Grafana/管理端口，只有授权客户端能访问。

可选方案：

1. Tailscale/Headscale：上手快，适合个人设备；
2. WireGuard：轻量，但需要自行处理密钥、路由和客户端配置；
3. IPsec/阿里云 VPN：更偏企业场景，配置复杂；
4. SSH 隧道：适合临时调试，不适合长期设备接入。

ESP32-C6 网关通常不方便直接加入 WireGuard，因此更现实的组合是：

- 网关 → MQTT over TLS（公网最小暴露）；
- 手机/电脑/Grafana 管理 → VPN 或安全组白名单。

安全组建议：

- MQTT TLS 端口可对设备网络开放，但必须配合认证/ACL；
- Grafana、API 管理端口优先只允许 VPN 或临时白名单；
- MySQL 不对公网开放；
- SSH/RDP 等管理端口只允许可信地址或 VPN。

## 6. 阿里云安全组建议（执行时再改）

维护时按“先加验证、后删除旧规则”的顺序：

1. 先确认新访问方式可用；
2. 再收紧旧端口；
3. 保留一个可恢复的管理路径；
4. 避免把自己当前公网 IP 写错导致失联；
5. 如用户正在使用网络，不切换网卡、不改变本地热点。

建议公网暴露原则：

- MySQL：不暴露；
- Mosquitto 明文 1883/9001：TLS 与设备迁移完成后关闭；
- MQTT TLS 8883/WSS：按需开放；
- Grafana：限制来源；
- API：区分公开只读接口和管理接口；
- SSH：仅可信地址/VPN。

## 7. 推荐维护窗口安排

一次只做一类改动，不建议通宵堆完。

1. **第一次窗口（30–60 分钟）**：账号/ACL，关闭匿名；
2. **第二次窗口（60–90 分钟）**：域名、证书和 MQTT TLS；
3. **第三次窗口（30–60 分钟）**：收紧安全组，管理入口转 VPN/白名单；
4. 每次结束后观察至少 24 小时，再进入下一阶段。

## 8. 需要用户后续判断的事项

1. 是否购买/使用独立域名；
2. 是否选择 Tailscale、WireGuard 或只用安全组白名单；
3. Grafana 是否需要公网访问；
4. 是否保留短期旧账号；
5. 证书方案使用阿里云免费证书还是 Let's Encrypt；
6. 维护窗口安排在不影响游戏/工作的时间。
